## Context

Non-ASCII characters in source code, shell scripts, configuration files, and documentation cause encoding issues across different environments (Windows, macOS, Linux, CI/CD pipelines). Debugging text garbling wastes significant developer time. All text files should use UTF-8 encoding, but content (comments, identifiers, documentation) should remain ASCII (English only) to avoid encoding mismatches.

Non-English content (comments, variable names, documentation) creates particular problems:
- Different developers may use different encodings depending on their language and locale
- CI/CD pipelines may use different locale settings
- Git diffs become unreadable when encodings mismatch
- Copy-pasting code between systems breaks

## Decision

**To eliminate time wasted on debugging text garbling, strictly adhere to the following rules:**

1. **Use ASCII characters only for code identifiers** (variable names, function names, class names)
2. **Ensure all files are encoded in UTF-8** (avoid environment-dependent encodings)
3. **Use English for all content** (comments, documentation, commit messages — non-ASCII content generates warnings)
4. **Allow non-ASCII in string literals only** (for user-facing messages, test data in Python code)

### Examples

**✅ Do this:**

```python
# File encoding: UTF-8 (default in Python 3)

def send_greeting_email(user_name: str, user_email: str) -> None:
    """Send greeting email to user."""
    message = "こんにちは"  # OK: string literal for user-facing message
    send_email(to=user_email, body=message)
```

**❌ Don't do this:**

```python
# ❌ Non-ASCII variable names (example: Japanese)
def メール送信(ユーザー名: str, メール: str) -> None:
    メッセージ = "こんにちは"
    send_email(to=メール, body=メッセージ)

# ❌ Non-English comment (example: Japanese)
def send_email(user_name: str) -> None:
    # ユーザーにメールを送信
    ...
```

**❌ Don't do this (Shift-JIS encoding):**

```python
# -*- coding: shift-jis -*-  ← FORBIDDEN
def process_data():
    ...
```

## Rationale

**Alternative: Allow non-ASCII identifiers (PEP 3131)**

While Python 3 allows Unicode identifiers, this creates encoding issues:
- Not all developers have the same keyboard layout
- Copy-pasting between systems breaks
- Git diffs are unreadable when encodings mismatch
- English is the universal language for code

**Alternative: Enforce encoding headers in all files**

Python 3 defaults to UTF-8 (PEP 3120), making encoding headers unnecessary. Adding them to every file creates noise without benefit.

**Alternative: Allow non-English content for local teams**

While this seems convenient for teams sharing a native language, it creates technical debt:
- CI/CD pipelines may use different locales
- Future international contributors cannot read documentation, comments, or scripts
- Translation tools (AI assistants, linters) work better with English
- Encoding issues can occur in shell scripts, configuration files, and documentation

## Consequences

- **Positive**: No encoding mismatches across environments
- **Positive**: Git diffs are readable on all systems
- **Positive**: Copy-pasting code works reliably
- **Positive**: International contributors can read code
- **Negative**: Non-English speaking developers must write all content in English
- **Negative**: Variable names cannot use natural non-English terms

## Compliance

**Out of scope:**

- `.claude/` -- generated by rulesync from `.rulesync/`. The `.rulesync/` sources are checked instead, so
  checking both would report every violation twice and cannot be fixed in `.claude/` anyway (regeneration
  overwrites it).
- `docs/adrs/` -- ADRs themselves may quote non-ASCII examples.

**Do:**

- Use ASCII characters for all identifiers (variables, functions, classes)
- Write all content in English (comments, documentation, shell scripts, configuration files)
- Ensure all files are saved with UTF-8 encoding (default in Python 3)
- Use non-ASCII characters only in string literals (user-facing messages, test data)

**Don't:**

- Use non-ASCII characters in variable names, function names, or class names
- Add encoding headers like `# -*- coding: shift-jis -*-`
- Write non-English content in comments, shell scripts, YAML, markdown, or other text files (warnings will be generated)
- Use legacy encodings (Shift-JIS, EUC-JP, ISO-8859-1, etc.)

**Acceptable non-ASCII usage:**

```python
# ✅ String literals for user-facing messages
ERROR_MESSAGE = "エラーが発生しました"

# ✅ Test data
def test_japanese_input():
    assert process("こんにちは") == "hello"

# ✅ Docstrings for public APIs (if targeting non-English users)
def send_notification(message: str) -> None:
    """
    Send notification to user.

    通知をユーザーに送信します。（Non-English explanations are allowed in docstrings only）
    """
    ...
```
